# Personal Tab — v0.3.0 CPU experimental

**書いた表現を覚え、ローカルで続きを提案するTab補完の初期実験版。**
GPU・モデルAPI・必須の機械学習フレームワークは不要です。通常の起動にはPython標準ライブラリのみを使います。

## 起動
```bash
python serve_demo.py --port 8765
```
`http://127.0.0.1:8765`を開き、記録・学習の許可を有効にします。
「コンピュータ。コンピュータ。」を手入力し、続けて「コンピ」と入力すると、既に書いた用語の続きを提案できます。
これは反復表現の動作確認例であり、未知文章への性能保証ではありません。

文末の灰色候補をTabで採用、Escapeで非表示。IME変換中は補完を抑制します。
実験版のため、非機密の文章だけを使ってください。複数タブの同時書き込みはサーバーの編集権で排他制御します。編集権はページを閉じると解放され、予期しない終了後は最大60秒で期限切れになります。

## 状態機械と操作の安全性

入力許可・IME変換・送信中・学習中・候補提示・候補の非表示・記憶の入替え・エラーを**明示的な状態**として表示します。
候補は編集番号・文書版・カーソル位置・補完方式・画面世代が一致するときのみ表示／Tab採用できます。入力が未承認の間は候補を表示しません。

**記憶の消去とJSON読み込みは確認操作が必要**です。学習許可を素早くOFF→ONしても入力同期を復旧し、古い応答は候補として採用しません。
[状態機械・アーキテクチャ仕様](docs/architecture-state-machine.md) に遷移条件と既知の制限を記録しています。

## 構成を確定した部分
- 親プロセス: 正本の文章・由来・版番号を保持し、候補を計算。
- 子CPUプロセス: 入力に基づく学習と、編集・削除時の再構築。プロセス異常終了は上限3回で自動再起動して、正本全文スナップショットから再学習。
- 学習要求は実行中一件＋最新待機一件。正本の入力イベントは失いません。
- 編集・削除・リセットで旧世代を失効。古い学習結果で削除前の記憶を復活させません。
- 追記時には少し古いモデルで予測でき、反映待ちを表示します。
- 貼付け・モデル由来は本人の手入力と区別し、無条件には学習しません。

ライブの予測器は用語メモリと統計予測です。これはQwenや汎用LLMの縮小版ではありません。
小型ニューラルの採用は未確定です。研究用GRU・Wikipedia比較器・過去の実験資料は、
別配布のフル研究アーカイブに保持しています。この公開構成はCPUランタイムとそのテストに絞っています。
ランタイムのPython/HTMLはフル研究チェックアウトと同一のソースです。

## 記憶を引き継ぐ / 暗号化自動保存（任意）
通常の学習状態はRAM内です。記憶を次回へ引き継ぐ方法は二つあります。

1. **暗号化自動保存（任意・推奨）**：入力の学習を許可後、12文字以上の合言葉を設定し「自動保存を有効化／復元」を押します。ブラウザのIndexedDBにAES-256-GCMで暗号化した本文と入力由来を保存します。鍵はPBKDF2-HMAC-SHA256・31万反復・16バイトのランダムsaltから作り、鍵・合言葉は保存しません。新しい起動時には同じ合言葉を再入力して復元してください。保存は確定イベントを受領した後、約450ms静止した際に行います。処理中・ブラウザ終了直前の最新入力は失われる可能性があります。
2. **手動JSON**：「記憶をJSONで保存（平文）」を押すと本文と入力由来を平文で取得できます。次回は確認してから読み込みます。機密性があるため安全な保管が必要です。

暗号化記憶は、このブラウザ・このオリジンのサイトデータにだけ保存します。合言葉を忘れたりブラウザデータを消去した場合、復元できません。他の端末への同期、自動サーバー保存、ディスク消去保証はありません。記憶リセットでは暗号化した自動保存データも消去します。既にダウンロードした平文JSONは消去されません。

**複数タブ**：各ページに異なる認証トークンを発行し、サーバーは同時に一つだけの編集権を与えます。別タブは書き込み・記憶取得・消去を拒否されます。前のタブを閉じたあと「編集権を再取得する」で引き継げます。旧タブに未送信の入力があった場合、控えを別欄へ保持するので手動でコピーしてください。自動で競合内容を混合しません。

メモリJSON、入力トレース、個人文書をGitに追加しないでください。

## CPUコンテナ
```bash
docker compose up --build -d --wait demo
# http://127.0.0.1:8765
docker compose down
```
ホストへの公開は127.0.0.1のみ。CPU二コア相当、メモリ512MBを上限に設定しています。
Dockerの設定と実ビルドの検証は区別します。GitHub Actionsでコンテナ起動・HTTP試験を実行します。

## テスト
```bash
python -m pip install -e ".[test]"
python -m pytest -q -rs
# ブラウザ試験も行う場合
python -m pip install -e ".[browser]"
python -m playwright install chromium
python -m pytest tests/test_browser.py tests/test_browser_dom.py tests/test_autosave_browser.py -q -rs
```
実HTTP＋子プロセス試験、通信を代替したDOM試験、実ブラウザHTTP試験を分けています。
管理ポリシーでlocalhost接続が拒否される環境では、最後の試験だけskipします。
CIでは`PERSONAL_TAB_REQUIRE_E2E=1`を設定し、接続拒否を成功扱いにしません。
同期比較用の起動は`python serve_demo.py --learning sync`。メモリ復元・ポーリングは通常の非同期モード向けです。
