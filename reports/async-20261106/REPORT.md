# CPU非同期初期版 v0.2.0 — 2026-11-06

## 結論
CPUの別プロセスへ統計・用語学習と再構築を分離した。モデル選定や文章予測の
品質改善ではなく、入力処理の停止時間を減らす実装である。GRUの非同期学習を
ライブエディタに採用したわけではない。CPU・ローカル・単一利用者の研究版。

## 追加機能
明示的な同意、入力来歴、イベント順序、文書版、世代付きモデル切替、最新待機
ジョブ一件への集約、編集後の古いモデル拒否、文末Ghost Text、Tab/Escape、IME
中の抑制、平文JSONのメモリ保存・復元、停止時の子プロセス終了。

## 実測条件
AMD EPYC 9V74、観測クロック2596.122MHz（固定なし）、共有Linux環境。
Python3.13.5。GPU不使用。標準ライブラリのみ、量子化・zero-pointなし。
バッチ1、計算プロセスごと1スレッド。非同期版は推論親＋学習子＋IPC用スレッド。
同梱Wikipedia抜粋を反復して作った20,000文字の負荷文章、200文字の高速追記、
冒頭2文字の置換。各方式は初期化し直して3回測定。人間のキー速度ではない。
通信・ブラウザ描画・IMEを含まないエンジン内の測定。

| 測定 | 同期版・3試行範囲 | 非同期版・3試行範囲 |
|---|---:|---:|
| 追記イベント受付 p95 | 0.096–0.164 ms | 0.185–0.202 ms |
| 2万文字文章の置換イベント受付 | 223.272–249.105 ms | 0.122–0.171 ms |
| 置換後の学習反映待ち | 0（受付内で完了） | 321.970–404.179 ms |

非同期版は短い追記ではオーバーヘッドが増えた。全処理が速くなったという結果
ではない。置換後の再構築完了まで古い学習を使わず、候補を出さない期間がある。
受付時間だけを「候補が使えるまでの遅延」と呼んではいけない。
最終的な統計カウンタは、3試行すべてで同期版と完全一致した。
`benchmark.json` に生の集計、環境、ジョブ集約数を保存。

## 検証
フル研究チェックアウト: 82件PASS、1件SKIP（最終検証時点）。
SKIPは管理ポリシーがChromiumからlocalhostへの接続を拒否する実HTTPブラウザ試験。
実HTTP＋実学習子プロセスの試験と、通信を明示的に代替したChromium DOM試験は別々にPASS。
DOM試験の通信代替を、本物のブラウザE2Eと称していない。OSネイティブIMEは未試験。
モード変更・カーソル移動後の遅延応答が古い候補を作る競合を再現して修正した。
削除・リセット中の遅延学習結果、保存復元時のモデル由来文字の混入、重複イベント、
不正インポートの原子性、ワーカー停止、学習要求の集約を検査した。
wheelビルド成功。Docker実ビルドはこの環境にDockerがなく未実施。

## 再現
```bash
python -m pytest -q -rs
python tools/benchmark_async.py --repeats 3 --size 20000 --output artifacts/new-async/benchmark.json
python serve_demo.py --port 8765
```
対象はフル研究チェックアウト。公開ランタイム配布では研究用のコーパスと比較器を
分離しており、アプリの起動とランタイムテストを提供する。

## 研究上の判定
H: 再構築のCPU処理を入力受付から外せば、受付の停止時間を抑えられる。
T: 同期・非同期を同じ負荷3試行で比較し、最終カウンタの一致も確認。
D: この負荷の入力受付分離と状態一致はPASS。文章品質と実際の時短は未判定。
C: 短い追記や低メモリ端末ではIPC・複製の費用が利益を上回り得る。
U: 共有CPU負荷、クロック未固定、3試行のみ、端末差、UIを含まないこと。
母集団への推定や合成不確かさ・被覆係数を根拠なく計算していない。

## 実装の一次資料
- Python3.13 multiprocessing: https://docs.python.org/3.13/library/multiprocessing.html
  明示的なspawnを使用し、モジュールimport時には子プロセスを作成しない。
- Docker Compose services: https://docs.docker.com/reference/compose-file/services/
  initとloopbackポート公開を設定。設定ファイルの存在と実Docker検証は区別する。
